# Arena 實驗計畫與審查紀錄

更新日期 2026-11-06。執行環境是隔離的 UnityTest2DProject 工作樹，使用 Unity `6000.0.31f1`。證據層級為 **Codex 本地回報**。GitHub 可獨立核對文件與此 PR 的變更範圍，執行資產和原始日誌仍在本地。從 `workflow_test_arena/main` 的乾淨 checkout 獨立重跑，尚未驗證。

## 實驗與審查原則

- **可行性**　用最小完整流程確認能做成。保留能解釋成功、失敗及適用範圍的證據。
- **順暢度**　優先找出等待、返工、環境阻擋、人工介入與重跑成本。補驗以可能改變下一步決策的缺口為準。
- **範圍**　解析度、版面微調、素材精修與完整產品 QA 不列入本輪。遇到細節直接阻斷操作或使結論失效，再記為問題。
- **證據**　分開標記本地實測、GitHub 可獨立核對的證據與未驗證項目。審查建議可並行，只有阻礙核心流程或使研究結論失真的問題才擋下一步。

## EXP-0016　重跑一次最小場景驗證

**問題**　同一個工作樹能否用一個固定入口重跑 EXP-0015 的場景、輸入與 Ink 檢查，避免每次寫完即移除臨時探針而觸發重新編譯。

1. **E16-01 場景**　用指定 Unity 版本開啟實驗場景，檢查 12 筆 Sprite 引用、玩家起點與兩個點擊區。命令輸出 Unity 版本及來源提交。
2. **E16-02 輸入與故事**　重用原本通過的滑鼠狀態序列，檢查兩個 ID、按住和空白點擊。分別重跑兩條故事路徑。明列手動推進的步驟與人工畫面驗收的界線。
3. **E16-03 重跑成本**　在已匯入的同一工作樹連跑兩次，記錄每次耗時、退出碼與各檢查結果。第二次須產出相同結果，且不需修改場景、套件或手動介入。若批次初始化失敗，記錄具體階段及日誌定位。
4. **E16-04 首次執行成本**　從執行倉庫的固定提交建立沒有 Unity Library 的 checkout，執行同一入口。記錄首次匯入耗時、總耗時、退出碼及是否需要人工介入。

本輪範圍限於可重跑的驗證入口，先沿用現有 Unity 與 Ink 設定。交付以本地執行證據與精簡 GitHub 摘要為準。是否納入正式流程，依兩次實測結果決定。

## EXP-0017　夜渡候船室

**問題**　第二個短場景能否沿用候車亭的雙熱區與 Ink 接線，並在改稿後快速確認故事仍能走通。

以候車亭場景為起點，建立另一個場景和獨立 Ink 故事，沿用點擊、Sprite 與對話元件。Runtime 腳本保持原樣。驗證入口增加 `RainyStopSmoke.RunFerry`，並檢查指定的開場台詞是否出現在 PlayMode。

| 步驟 | Unity 耗時 | 結果 |
| --- | --- | --- |
| 搭建並首次執行 | 94.08 秒 | 退出碼 0，場景、開場白與兩條故事路徑通過。 |
| 只改一句 Ink 開場白並重跑 | 22.01 秒 | 退出碼 0。Unity 更新 JSON，PlayMode 讀到新台詞，兩條路徑仍通過。 |
| 重跑原候車亭 | 20.27 秒 | 退出碼 0，原場景與兩條路徑通過。 |

從開始盤點到首次驗證完成約 3 分 10 秒。表內只計 Unity 程序的啟動到退出。三輪共 11 項檢查通過，無人工操作或重試。結果屬 Codex 本地回報，使用 Unity 6000.0.31f1 的已匯入工作樹，資產與紀錄整理於執行倉庫本地提交 `e310966`。Unity Test Runner 執行零項。

兩個相同互動結構的場景已能共用 Runtime，單句改稿的重跑成本接近原場景驗證。此結果適用於雙熱區流程。下一次遇到不同互動結構時，再檢查是否值得抽出共用工具。

## EXP-0018　單熱區訊號亭

**問題**　同一個世界物件能否在沒有畫面選項的情況下推進兩次 Ink 狀態。原型沿用既有互動元件，場景僅有一個可點擊拉桿。

| 驗證 | Unity 耗時 | 結果 |
| --- | --- | --- |
| 原接線 | 31.65 秒 | 退出碼 1。第一次世界點擊已送出事件，橋接因沒有選項而未推進。 |
| Ink 等待標記 | 23.49 秒 | 退出碼 0。兩次點擊依序送出訊號、收到回訊，第三次保留結局。全程無選項。 |
| 既有場景回驗 | 19.71 秒及 19.97 秒 | 候車亭與夜渡各自退出碼 0，場景及兩條故事路徑均通過。 |

最小修正是在 Ink 當前台詞帶 `await-world-click` 時，允許無選項狀態接收世界點擊。結局沒有等待標記。這區分了等待世界輸入與故事結束，原互動元件及兩個既有場景沿用原樣。結果來自 Unity 6000.0.31f1 的本地 PlayMode 逐步輸入檢查，實驗提交為本地 `eb75fe3`。Unity Test Runner 執行零項。
